# V3-EXT-001 — External dataset audit

Date: 2026-08-21

This audit records dataset properties before DCHAG v3 external scoring. It is intentionally conservative: attack labels are not treated as defensive-control intervention truth.

## Candidate A — LANL Unified Host and Network Data Set

Source: https://csr.lanl.gov/data/2017/

Documented properties:

- approximately 90 days of events from an operational LANL enterprise environment;
- host and network data are deidentified but identities match across the two sources;
- Windows host events include authentication/logon activity and process-related fields;
- network records include source/destination devices, ports, protocol, packets and bytes;
- LANL states that, to the extent possible under law, copyright and related rights are waived;
- the dataset was approved for public release and was reviewed under LANL human-subject procedures.

Assessment:

- real operational anchor: HIGH;
- human/user event observability: MODERATE-HIGH;
- business-process semantics: LOW;
- technical-state observability: HIGH;
- intervention ground truth: NONE;
- cross-source temporal correlation: HIGH.

Decision: `PRIMARY_REAL_ANCHOR`.

Use in v3: estimate real temporal/user/process/network distributions and test transportability/prediction/structure stability. Any control-effect truth must be introduced only through an explicitly documented semi-synthetic intervention layer.

## Candidate B — LANL Comprehensive Multi-Source Cyber-Security Events

Source: https://csr.lanl.gov/data/

Documented properties:

- 58 consecutive days of deidentified enterprise events;
- five sources: authentication, process start/stop, DNS, network flow and red-team events;
- roughly 1.65 billion events, 12,425 users, 17,684 computers and 62,974 processes are documented by the source;
- red-team events identify known malicious behavior.

Assessment:

- real operational anchor: HIGH;
- human/user event observability: HIGH for identity/action traces but not human cognition;
- business-process semantics: LOW;
- technical-state observability: HIGH;
- attack ground truth: PARTIAL/HIGH through red-team events;
- intervention ground truth: NONE.

Decision: `PRIMARY_REAL_ANCHOR`, subject to download/processing feasibility.

Use in v3: strong candidate for user→process→technical temporal path construction and attack-path validation. Red-team annotations must not be reinterpreted as counterfactual defensive-control effects.

## Candidate C — DARPA Operationally Transparent Cyber (OpTC)

Source: https://github.com/FiveDirections/OpTC-data
Program background: https://www.darpa.mil/research/programs/transparent-computing

Documented properties:

- public-domain release according to the dataset README;
- approximately two weeks of a highly instrumented enterprise-scale evaluation;
- benign activity followed by malware injection by a red team, with benign traffic continuing during attack activity;
- data collected from roughly 500 hosts because of collection limits;
- structured provenance data plus red-team ground truth;
- DARPA Transparent Computing explicitly targets provenance, causal dependencies among system components and end-to-end behaviors.

Assessment:

- real/operational realism: MEDIUM-HIGH (instrumented evaluation environment rather than ordinary production operations);
- human/user event observability: MODERATE;
- business-process semantics: LOW;
- technical/provenance observability: VERY HIGH;
- attack ground truth: HIGH;
- intervention ground truth: NONE for defensive-control effects.

Decision: `PRIMARY_REAL_ANCHOR` for technical/provenance external validation; not sufficient alone for the full socio-technical DCHAG contract.

## Candidate D — CERT Insider Threat Test Dataset

Source: https://sei.cmu.edu/library/insider-threat-test-dataset/
DOI: 10.1184/R1/12841247.v1

Documented properties:

- explicitly synthetic background and malicious-actor data;
- generated by CERT/SEI with ExactData under DARPA sponsorship;
- answer keys describe malicious activity, scenarios and synthetic user identifiers;
- designed to address the scarcity of usable insider-threat datasets.

Assessment:

- real operational anchor: NO;
- human/organizational semantics: HIGH relative to most cyber telemetry datasets;
- technical activity: HIGH enough for insider-threat scenarios;
- scenario ground truth: HIGH;
- real-world external validity: NO;
- defensive-control intervention truth: NONE unless separately generated.

Decision: `SYNTHETIC_SOCIO_TECHNICAL_ANCHOR`.

Use in v3: useful to enrich and stress the human/organizational layer and to test semantic portability, but it must never be described as real-world external validation.

## Current selection

The external-validation design will not depend on a single dataset.

Preferred roles:

1. LANL Unified / Comprehensive Multi-Source: primary real user-host-network temporal anchor;
2. OpTC: primary provenance/attack-path external anchor;
3. CERT Insider Threat: synthetic socio-technical scenario anchor only.

## Consequence for DCHAG v3 claims

The planned validation must separate three claims:

- `causal-effect recovery`: tested only where an intervention oracle is explicitly constructed and documented;
- `external transportability`: tested on real or operationally realistic traces without claiming true counterfactual effects;
- `socio-technical semantic portability`: may also use CERT synthetic insider scenarios, clearly labeled as synthetic.

## Next gate

Before model execution, create a compact acquisition sample or documented subset from at least one `PRIMARY_REAL_ANCHOR`, record checksums and parsing schema, and freeze the mapping from source fields to DCHAG H/P/T/C roles before inspecting DCHAG performance.
